# UX / information architecture review (agent, Oct 21 2026)

The page fails the 5-second test. "Did today's run happen?" is spread across four widgets, and none of them compares the run against today's ET date. "Am I up or down?" gets a bare dollar figure. On a phone at 390px the page scrolls sideways.

## P0: trust and the daily glance
1. **TodayBanner** (Bits.tsx), shown on the Overview and /shorting. One full-width line, colored by state, e.g. "TODAY Tue Oct 21 · EXECUTED 15:55 · 5/5 filled · Day −$42 (−0.4%)". Other states: SCAN IN 2h14m, NO RUN TODAY (expected 15:45), DRY RUN ONLY, MARKET HOLIDAY, FAILED: msg. Data: short_runs.run_date/status/mode/n_orders. Holidays need a run row or session_close from the bot.
2. **Phone layout.** Nothing may overflow the body. Stack the grids under 720px and give grid children `min-width:0`. Only tables scroll, inside .scroll. Hide the command bar under 720px.
3. **Day P&L as the hero number**, in $ and %. Equity shows "as of" or live. Open P&L shows %. Since-start shows %, with an explanatory note until data exists.
4. **Dry run vs live must be unmistakable.** Picks read "WOULD SHORT" on a dry run, and a DRY RUN / LIVE pill appears in the page head and on the book panel. Demo positions are either not fabricated for dry runs or labeled SIMULATED.
5. **Heartbeat bug.** sync.py's heartbeat("ok") overwrites the run's warning or error, so a bad run can show HEALTHY. Split bots into last_run_status / last_run_at / last_sync_status / last_sync_at, or have sync leave run_state alone. BotPill takes the worse of the two. heartbeatAge uses the browser's local getDay; it should use ET.
6. **Next-run countdown** pill next to the clock (SCAN T−, TRADE T−). /shorting gets a 4-step timeline: Scan 15:45 → Trade 15:55 → Cutoff 15:58 → Sync 16:15, each showing done, pending or failed with the actual time.

## P1: managing the bot
7. **Run history** at /shorting/runs, with a drill-down page per run at /shorting/runs/[id]. Each run shows the next day's P&L for its book (needs short_trades.run_id).
8. **Run log / errors panel.** New tables run_events(run_id, at, level, step, message) and sync_runs. The bot gets a logging handler that batches WARN-and-above lines to Supabase. Also show data-source health per run.
9. **Risk panel.** Shows gross %, buying-power cushion, largest position %, sector concentration, and the overnight $ loss if every name gaps +20% or +50%. Each held name carries its SI/DTC and flags, joined from its entry run's scan.
10. **Adverse-move alerts.** monitor.py runs every 15–30 minutes during market hours and writes to an alerts table (push via ntfy is optional). Thresholds: ALERT_POSITION_LOSS_PCT=25, ALERT_BOOK_LOSS_PCT=5. The dashboard shows a red alert bar.
11. **Fill quality.** Show slippage against the scan's close and time-to-fill.
12. **Blotter grouped by rotation day**, with subtotals, a cumulative realized P&L line, and 7d/30d/all filters.
13. **Explainability.** Add a "3 Borrow" column, a weights legend (35/20/10/35), and a row drawer with the raw inputs.
14. **Glossary tooltips** via an `<Abbr term>` component (tap on mobile). Humanize the flags and color them good or bad for a short.
15. **Group the scan board** with divider rows: PICKED, ELIGIBLE BELOW TOP 5, EXCLUDED. Collapse EXCLUDED by default on mobile.
16. **Mobile card view** for positions and picks. Put positions first on mobile.
17. **Empty states.** A nextRun() helper that knows weekends. Prefix the tape with the scan date. A failed run shows the rerun command.
18. **Command bar.** Commands: TICKER lookup, RUNS, RUN <date>, LOG, RISK, BT. `?` opens a shortcut overlay. Add 1–4 and g-shortcuts; F-keys clash with Mac media keys.
19. **Auto-refresh**: router.refresh() every 30s during 15:40–16:20 and every 5 min in market hours. Label each panel as of its time, and show snapshot taken_at.
20. **Collapse inactive and planned bots** into one slim row. The shorting card gets a 5-day P&L sparkline.
21. **Performance panel**: max drawdown, current drawdown, Sharpe/Sortino, profit factor, average win/loss, best/worst day, and P&L by rank slot, by catalyst and by score bucket.

## P2: Options
22. **/options as a backtest lab**: a comparison table, overlaid equity curves against SPY, an underwater chart, a monthly heatmap, a run detail page with params and trades, and later a Greeks/positions tab. Schema: options_backtests, options_bt_equity, options_bt_trades.
23. **Label backtests as hypothetical**, with the fill assumptions and code version, styled distinctly from live data.
24. **Lucid gets a secondary nav slot** until it's active. Its eventual layout: a distance-to-MLL bar per account.
25. **Signed-in email in the status bar**, and a PWA manifest.

Build order: 2, 1, 4, 5, 3, 16, then 7/8/9, then 22.
